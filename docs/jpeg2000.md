# Managed JPEG 2000 decoding

`Render.NET.Jpeg2000` is an original C# decoder targeting .NET 10. It accepts JP2 containers and raw JPEG 2000 Part 1 codestreams. It has no NuGet, native, graphics, or external-process dependency. Its source is covered by this repository's MIT license. CoreJ2K and JJ2000 code are not included.

```csharp
using Render.NET.Jpeg2000;

Jpeg2000Image image = Jpeg2000Decoder.Decode(
    File.ReadAllBytes("scan.jp2"),
    new Jpeg2000DecodeOptions { MaximumPixels = 4_000_000 },
    cancellationToken);

Jpeg2000Component red = image.GetComponent(0);
ReadOnlyMemory<int> nativeSamples = red.Samples;
int sample = image.GetSample(x: 20, y: 10, component: 0);
```

The result retains integer precision, signedness, and each component's native sampling grid. `GetSample` expands subsampled components with nearest-neighbour lookup. Reversible and irreversible multiple-component transforms are reconstructed before samples are returned. Colour conversion from JP2 sYCC or external PDF colour spaces belongs to the caller. `ColorSpace`, `AlphaComponent`, `PremultipliedAlpha`, and `HasIccProfile` describe container metadata; the component API does not perform ICC conversion or alpha compositing.

`Render.NET.Pdf` uses this decoder automatically for `JPXDecode`, including raw codestreams. It interprets the PDF colour space when present, supports gray/RGB/sYCC container colours without an external colour space, and applies `SMaskInData`, external masks, and colour-key masks. PDF `Decode` arrays are ignored for JPX images as required by that filter. Embedded ICC profiles without an external PDF colour space are reported as unsupported.

## Implemented subset

| Area | Support |
| --- | --- |
| Container | JP2 signature, compatible brand, image header, codestream, enumerated sRGB/gray/sYCC, whole-image alpha definition, 32/64-bit box lengths |
| Components | 1–16 components, 1–16-bit signed/unsigned samples, component subsampling, nonzero image/tile origins |
| Wavelets | Reversible 5/3 and irreversible 9/7; up to 16 decomposition levels |
| Coding | MQ arithmetic decoding, significance/refinement/cleanup passes, raw bypass, context reset, termination per pass, vertical causality, predictable termination coding, segmentation symbols |
| Packets | LRCP, RLCP, RPCL, PCRL, CPRL; quality layers, precincts, tile-parts, SOP/EPH |
| Quantization | No quantization, scalar derived, scalar expounded; component overrides; ROI maxshift |

POC progression changes, PPM/PPT packed packet headers, JP2 palettes/component remapping, arbitrary channel remapping, coding changes across tile-parts, extended profiles/Part 2 transforms/HTJ2K, and larger precision/decomposition limits are explicitly unsupported. Predictable termination is decoded, but its termination pattern is not separately validated. The decoder is not an encoder or a complete codestream integrity validator.

Malformed/truncated structures and configured resource-limit violations produce `InvalidDataException`. Unsupported features produce `NotSupportedException`; cancellation produces `OperationCanceledException`. PDF preserves its existing strict/default unsupported-feature behavior.

## Limits and verification

Defaults bound encoded bytes to 128 MiB, reference-grid pixels to 16,777,216, packets across the image to 1,000,000, and cumulative working allocations to an estimated 512 MiB. `ExpectedWidth` and `ExpectedHeight` validate dimensions before sample-buffer allocation. Cancellation is checked during marker/packet interpretation, coding passes, wavelet reconstruction, and sample assembly. The allocation budget accounts for sample buffers and estimates metadata; it is not a hard process-memory cap.

The implementation follows the algorithms and format definitions in [ITU-T T.800 (11/2015), JPEG 2000 Part 1](https://www.itu.int/rec/T-REC-T.800-201511-S). No reference decoder source was incorporated.

`Tests/Fixtures/Jpeg2000` contains 70 original synthetic cases and expected pixels decoded independently by OpenJPEG 2.5.4, with hashes. The reversible cases match exactly; the three irreversible/modified-quantization cases allow a maximum difference of one component level. Tests also exercise PDF colour spaces and masks, cancellation, resource limits, malformed headers, unsupported extensions, and concurrent decoding. This coverage does not establish complete standard conformance or production throughput. OpenJPEG was used for independent verification and is not included in package contents or dependencies.
